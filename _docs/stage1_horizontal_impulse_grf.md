# 水平床反力：絶対力積方式（layoutVersion=2）

## 変数構成

基本状態 vx0, thetaL, r0 の3個、時間 stanceScale, duty の2個、水平方向 n 個、鉛直方向 nz 個。質量は m とし、鉛直制御点数との混同を避ける。水平は離散変数 k、連続変数 Ix、n−3 個の制御点大きさ、独立な端点傾き2個。最大値点 j とその傾き固定は廃止。n=15,nz=9 では連続変数29個、等式制約3本。

水平内部値の絶対値和1はスケールの重複をなくす。形状そのものが一意に決まるわけではなく、多数の候補から最適化で選ぶ。

## 形状と積分

f1=fk=fn=0、kの前は負、後は正。自由な値は非負の大きさとして持ち、符号を付ける。内部無次元傾きは beta_i=(f_(i+1)−f_(i−1))/2、両端は独立に [-0.5,0]。区間極値で符号を確認し、旧来の最大振幅による |f(t)|<=1 制約は外す。ゼロ区間を排除する面積条件と小さな正値の下限は従来同様に残す（数値上の符号余裕は1e-4）。

    S0 = sum(f_i) + (beta_1-beta_n)/12
    Sx = sum(abs(f_i)) + (2*beta_k-beta_1-beta_n)/12
    CH = sum((i-1)*f_i) + beta_1/30 + sum(beta_interior)/15 - (5*n-7)*beta_n/60

等式制約は S0=0 と sum(abs(f_i))=1。探索途中にも実際の和を使い、1への置き換えはしない。符号条件が成立すると dt*Sx は形状の絶対値積分。符号違反候補では符号を指定した左右面積の差であり、厳密な絶対値積分とは異なる。違反候補は区間極値制約で排除する。

## 時間と運動

    L = 2*abs(r0*sin(thetaL))
    meanV = vx0 + Ix/(m*Sx)*(S0-CH/(n-1))
    TsBase = L/meanV
    Ts = stanceScale*TsBase
    dt = Ts/(n-1)
    Ax = Ix/(dt*Sx)
    Tf = Ts*(1-duty)/duty

Sx>0, meanV>0 が必要。条件を満たさない候補は計算失敗ペナルティ。軌道中の瞬間水平速度の下限は追加しない。S0=0 のとき、ユーザー提示の TsBase=L/(vx0-Ix*CH/(m*(n-1)*Sx)) と一致する。探索途中でも x(Ts)-x(0)=stanceScale*L が整合する。

Fx=Ax*f(t) とし、多項式を1回・2回解析積分して速度・位置を求める。時間倍率でAxは逆比例し、水平速度変化は維持される。鉛直側では1周期分の力積 mgT と重心高さ周期条件から振幅・初期鉛直速度を決める。

## 探索と初期範囲

離散走査は3<=k<=n−2。restrictGrfK=trueならgrfKSelectionに限定する。startsPerKは各kに配る開始点数。n=15で2,000点/kなら総数22,000。広域探索後に最良kを固定して狭域探索と密な軌道の修正を実施する。

開始点の水平値は両側に配る総量を調整して正規化・正味力積0を満たすよう生成する。端点が異なる場合は負側の総量を 1/2+(beta_1-beta_n)/24 とする。鉛直値も和1にする。形状符号・脚モデル等の実行可能性までは開始点に保証しない。狭域探索では狭域ボックス内をサンプルし、等式制約はソルバーで満たす。

Ix の既定範囲は [0.1,4.0,1.13] N s。既存trajectory.csvの台形積分から、20261108_184726_939 は1.130093、173633_989 は1.985427、152400_951 は1.842536 N s。1.13を初期値とし、既存実績より広い有限範囲を設定した。

## 出力と旧実行との互換

設定に index と parameterGroups を保存し、ベクトル位置と分類を明示する。horizontal_grf_control_points.csvに全点の符号付き値・時間傾き・床反力を、horizontal_grf_beta.csvに無次元傾きを保存。horizontal_grf_summary.csvにIx, Ax, S0, Sx, CHと正味・左右符号付き力積を保存する。Az,Sz,Czはreportに出力しない。

新規ルートは configure_impulse_grf → optimize_impulse_two_stage → prescribed_impulse_motion_stage1 を使用する。旧(k,j)用関数は旧設定の処理を保つために残すが、新規ルートからは使用しない。共通のシミュレーション・出力関数はlayoutVersionで分岐する。過去ログ・ソーススナップショットは編集しない。
