# 段階的な基本パラメータ探索

`run_stage1_basic` は phase1 → phase2 → phase3.1 → phase3.2 の順で実行する。
各段階は広域／狭域の二重MultiStartではなく、指定開始点数のMultiStartを各基本パラメータ・kに対して1回実行する。
従来の単段探索は `main_stage1_basic(options)` に残している。

| 設定 | 既定値 | 意味 |
|---|---:|---|
| starts_phase1 / starts_phase2 | 50 / 100 | 各組・各kの開始点数 |
| n_phase1, k_phase1, m_phase1 | 7, 4, 5 | phase1の形状自由度。α=1固定 |
| pass_phase2 | 50 | 実行可能な基本パラメータ組をコスト順で選ぶ割合[%] |
| n_phase2, m_phase2 | 9, 6 | α固定解除、k=3,…,n−2を全探索 |
| starts_phase3 | [200 200] | 各詳細探索の開始点数 |
| pass_phase3 | [25 10] | 各詳細探索へ進む基本パラメータ組の割合[%] |
| n_phase3, m_phase3 | [11 13], [7 9] | 詳細探索ごとの制御点数 |
| kRadiusFraction | 0.10 | phase3.1で使う相対零交差位置の半幅 |
| refinementRadius | 0.20 | 親の探索幅に対する詳細探索の半幅 |
| stopAfterPhase | Inf | 1=phase1, 2=phase2, 3=phase3.1,…まで実行 |
| generatePhaseOutputs | true | 各phaseで従来の図・動画・マップ・PCAを生成 |

phase3配列の長さを増やせば段階を追加できる。開始点数・n・mはスカラーなら各段階に共通適用する。
基本パラメータ範囲・目標値・重み・Duty等は従来と同じ設定を使用する。

## 選抜・分割

実行可能判定は従来どおり評価点での最大制約違反と許容値による。
同じ基本パラメータ組の中で最小の実行可能コストを採用し、異なる組を順位付けする。
通過件数は `ceil(実行可能な組数 × pass/100)`。コスト値の割合ではない。
phase1の不成功組は除外する。この扱いは探索方針であり、物理的な実現不能の証明ではない。
phase2は親の解を初期値にせず、全域で再生成する。

詳細探索では各軸の親格子間隔をΔとし、±Δ/3の8頂点を探索する。
子の格子間隔はΔ/3として保存する。nまたはmが変われば中心も再探索する。
最初の指定基本範囲を超える子は除外し、重複した探索組は統合する。
親の実行可能結果も候補として残し、制御点数が違う場合も元の設定で比較・再構成する。
親の保持によって前段階の最良コストが失われることはない。

零交差位置は `rho=(k-1)/(n-1)` で保存する。
phase3.1は各親の上位2位置について±kRadiusFraction内のkを探索する。
新しい格子が粗い場合にも各上位位置の最寄りの有効kを含める。
phase3.2以降は各親の上位2位置に最も近いkだけを使用する。同じkへ丸められた場合は1個となる。
`selection.mat` に基本組ごとの上位2位置・コスト・ケースIDを保存する。

## 親の解と探索幅

phase2からphase3.1では、基本パラメータの選抜・細分化と相対k範囲だけを引き継ぐ。
時間・床反力パラメータの上下限は、実行窓口で指定した元の広域範囲へリセットする。
制御点数に合わせて補間したphase2解はMultiStartの第1開始点として含めるが、他の開始点は広域範囲から生成する。
phase2の親結果自体も比較候補として保持する。

phase3.1からphase3.2以降は局所探索へ移る。

phase3.2以降の各連続変数の新しい範囲は、親解を中心として
`[親解 − 0.2×親の範囲幅, 親解 + 0.2×親の範囲幅]` とし、当初の物理的上下限で切る。
0の変数も親の幅があれば動く。基本3変数はこの範囲式ではなく上記格子分割で決定する。
制御点数変更時は親の節点値を線形補間し、節点数比でスケールする。
水平零交差位置を移す場合は、その前後の時間座標を個別に伸縮して符号領域を維持する。
正規化・水平力積ゼロを再調整した形状を中心とし、探索幅も補間・スケールして対応付ける。
端点βは節点間隔比を掛ける。変更後の形状が元軌道と完全一致するとは限らないため、親結果は別に保持する。
局所開始点はボックス内で生成し、水平正負の節点和と鉛直節点和を有界射影で調整する。
非負性・符号・摩擦・機構等の非線形制約を満たすことまでは開始点生成で保証しない。

## 保存と再開

`_logs/stage1_basic/日時/phase1`, `phase2`, `phase3.1`, …に保存する。
各phaseの `settings.mat` にタスク一覧、`cases/` に組ごとの最終結果を保存する。
進捗・完了状態は `checkpoint.mat` に一時ファイルから置換して保存し、不変のタスク一覧には上書きしない。
完了ケースは一時ファイルから置換する。途中中断したケースだけ再実行し、完了済みケースは変更しない。
各結果には親の由来、格子間隔、モデル設定、探索上下限を保存する。詳細なソルバー履歴は保存しない。

```matlab
[summary, folder] = run_stage1_basic(struct('stopAfterPhase', 2));
% 後から残りの段階を実行
[summary, folder] = run_stage1_basic(struct('resumeFolder', folder));
% 一つのphaseのパスを指定しても、親の実行フォルダを識別して再開する
% 全phase完了後、最終結果を親にしてさらに詳細探索を1段追加
extra=struct('starts',200,'pass',10,'n',15,'m',11);
run_stage1_basic(struct('resumeFolder',folder,'appendPhase3',extra));
```

再開時は保存済みの物理・探索設定を使う。resumeFolder、stopAfterPhase、generatePhaseOutputsを実行制御に使う。
appendPhase3は全phase完了後だけ使用でき、既存の結果を変更せず詳細探索の予定を追加する。
phaseのケースファイルが正本であり、summary.csv/reportは再構築できる。
中断したphaseの図出力は再実行される。最適化だけ完了させた場合も後から図出力を有効にして再開できる。
ルートのsource/には実行開始時のソースを保存する。コード変更後に厳密な再現が必要なら、そのソースを利用する。
少ない格子点数で検証したい場合は各基本設定を `[中心 0 1]` とする。

詳細格子のマップは不等間隔の実座標に対応したセルで描く。断面が8枚以上になる場合は7枚ずつに分ける。
段階探索では未探索の組も存在するため、マップの黒い領域だけで失敗と未探索を区別しないこと。
実際の探索有無・成否はsummary.csv/casesで確認できる。
