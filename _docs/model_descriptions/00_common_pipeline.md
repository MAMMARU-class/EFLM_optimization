# 3モデル共通の運動・最適化・高速化

## 共通の入力と座標

探索ベクトルは

\[
 a=[A,\alpha,v,D,r_0]
\]

で、順に水平床反力の振幅 [N]、接地時の脚角 [rad]、初期水平速度 [m/s]、duty比、初期脚長 [m] を表す。`v` は1歩の平均速度ではない。リンク寸法と総質量は [`robot_parameters.m`](../../common/parameters/robot_parameters.m) で固定し、`r0` だけを探索する。`p.leg` は既定の初期候補の脚長、`p.lengthScale` は数値正規化の固定長である。

立脚では世界座標を `+x` 右、`+z` 上とする。接地足先を原点に固定すると、胴体から足先へのベクトルは `Y=(-x,-z)` である。図と動画は進行方向を左に表示するが、計算の `+x` は変えない。

## 胴体を先に解く

[`prescribed_motion.m`](../../common/function/prescribed_motion.m) は、探索変数から立脚時間 `Ts=2r0 sin(α)/v`、遊脚時間 `Tf=Ts(1/D−1)`、周期 `T=Ts+Tf` を求める。接地時の胴体位置は `x0=−r0 sin(α)`、`z0=r0 cos(α)`、鉛直速度は `vz0=−gTf/2` とする。

\[
 F_x(t)=-A\sin(2\pi t/T_s),\qquad
 F_z(t)=\frac{\pi mg}{2D}\sin(\pi t/T_s),\quad 0\le t\le T_s.
\]

立脚中の `m ẍ=Fx`、`m z̈=Fz−mg` を解析積分して `x,z,vx,vz` と床反力の時間微分を一括計算する。脚姿勢の解法を変えても、**同じ探索ベクトルを入れたときの胴体軌道は同じ**である。遊脚は離地位置・速度を初期値とする弾道計算で、脚姿勢と遊脚トルクは評価しない。

立脚時刻は `t=Ts[1−cos(u)]/2`、`u∈[0,π]` で配置する。接地・離地近傍に点を集め、与圧の立ち上がりや制約の急な変化を少ない点数で捉える。床反力の積分条件によって鉛直速度・高さの周期残差は解析上ほぼゼロになるが、最適化では接地脚の幾何やモータ・関節制約も別途評価する。

## 共通のばね・モータ・目的関数

approx/exactで使う共通ばね則は、`s=ds`、`u=clamp(s/δe,0,1)`、`ρ=3u²−2u³` として

\[
 F_s(s)=k_ss+F_{pre}\rho,\quad
 k_s=17430\,\mathrm{N/m},\ F_{pre}=3.4\,\mathrm N,\ \delta_e=0.05\,\mathrm{mm}.
\]

[`spring_response.m`](../../common/function/spring_response.m) はこの反力、接線剛性、積分したポテンシャルを返す。`ks*s` は全領域で入る。`s<0` もNewton反復を続けるための数値的延長として評価するが、最終的には制約違反となる。EFLMの実際の運動方程式での与圧の扱いは別方式であり、[EFLM文書](03_EFLM_five_coordinates.md)に記す。減衰は0である。

股・膝のモータ回転速度から、[`motor_envelope.m`](../../common/function/motor_envelope.m) が関節軸の符号付きTN上限・下限を計算する。トルクのクリップはせず、範囲外を不等式制約とする。評価する機械仕事は

\[
 E_{act}=\int_0^{T_s}(|\tau_h\dot h|+|\tau_k\dot k|)\,dt,
 \qquad CoT=\frac{E_{act}}{mg\,\Delta x}.
\]

台形則による積分を使用し、回生を仮定した正負仕事の相殺はしない。目的関数は `w2*CoT−w1*平均速度` を最小化する。`平均速度=Δx/T` である。ばねポテンシャル自体を目的関数へ加算しないが、ばね反力が姿勢・トルク・角速度を変えるため、間接的に機械仕事へ影響する。

共通制約は股・膝角、関節軸のモータ特性、`0≤s≤15 mm`、床への胴体のめり込み禁止、正の移動距離、立脚・遊脚の各0.2秒以上である。**現行コード**の股角は10–170度、膝角は16–144度であり、旧設定の股角55–155度とは異なる。足首に独立した角度制限はない。最終判定は離散時刻での最大違反と、周期残差を使う。

## 最適化の実行経路

[`run_elastic_optimization.m`](../../run_elastic_optimization.m) でモデルを指定し、[`main_elastic.m`](../../common/optimization/main_elastic.m) が条件の検証、モデル別の幾何キャッシュ、ログフォルダを用意する。共通の [`optimize_two_stage.m`](../../common/optimization/optimize_two_stage.m) は評価関数だけを切り替える。

1. 5変数をそれぞれの探索上下限から `[0,1]` に正規化し、広域MultiStartで複数のSQPを走らせる。候補の半数は立脚・遊脚時間が下限付近になる接地条件から作る。格子探索は使わない。
2. 広域解の周囲を縮め、狭域MultiStartを行う。
3. 通常121点で評価した解を1201点で再確認する。各制約が厳しくなる時刻を選び、必要なら密な軌道上でSQPの修正を行い、確認できた実行可能解を保持する。
4. 数値・軌道・最適化履歴・グラフ・動画・実行時ソースを `_logs/<モデル>/<日時>` に保存する。最適化中に動画を描画しない。計算できない候補はペナルティとして扱う。1評価と各段階には時間上限がある。

## 速度を優先した共通実装

- 胴体ODEを各候補で数値積分せず、規定床反力を解析積分する。飛行も弾道の閉形式で計算する。
- 脚の質量ゼロというモデル仮定に従って、脚の微分方程式を積分せず、各立脚時刻で小さい代数系を解く。これは脚内部の慣性を省く**モデル上の仮定**でもあり、単なる計算上の近道ではない。
- 立脚の全時刻を配列で同時に処理する。目的値と制約を同じ探索点で要求されたときは、直前のシミュレーション結果を再利用する。
- 広域段階は121点、最終確認は1201点に分ける。最終修正では制約が厳しい時刻を選び、全時刻の制約を毎回SQPへ渡す負担を抑える。ただし候補の最終判定は密な軌道で行う。
- 動画とグラフの作成、CSVへの書き出しは最適化後にまとめて実行する。
- 広域・狭域MultiStartは4プロセスワーカーで開始点を分担する。最終修正のSQPはクライアントで実行する。各ワーカーの評価履歴・失敗・反復数はキューで集約する。Parallel Computing Toolboxが必要で、利用できない場合は明示的なエラーとする。
- approx/exactは各候補でゼロ伸びの幾何から初期値を作り、全時刻を一括して解く。初期値の候補間・時刻間の引き継ぎは行わない。

ルート実行関数では `overrides.useParallel=true`、`overrides.parallelWorkers=4` が既定である。`useParallel=false` で直列実行できる。既存のプールが指定人数と異なる場合は `delete(gcp('nocreate'))` で閉じてから再実行する。幾何の成立条件と残差の判定は各評価で行う。

これらにより評価1回の費用を下げるが、各モデルの壁時計時間を一律に保証するものではない。収束しない候補、制約の形、SQPの反復数によって総時間は変わる。
